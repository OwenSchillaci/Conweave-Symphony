SYMPHONY EGRESS MARKING SCOPE
============================

Method
------
Profile D, 524,288-byte nominal chunk, seeds 1–3. Each seed has
DCQCN only (SYMPHONY_MODE 0), original switch-wide Symphony (2),
and experimental egress-aware Symphony (3). The experiment keeps
the topology, tuples, dependency graph, ECMP paths and DCQCN
settings fixed. Every run completed all 640 transfers. The new
instrumented off/on controls reproduced the archived transfer
timestamps, step timelines, routes and mark totals at all three
seeds. Every original Symphony mark also reproduced its timestamp,
flow, switch, packet sequence, reference step, probability and
random draw. The comparison used a temporary rebuilt executable
linked against the checkout's existing modules and ran no 8 MB jobs.

The gate uses a locally observable queue signal. QbbNetDevice
reports successful enqueues. SwitchNode counts ring packets by
egress, collective and logical step. Normal dequeue and link
drain remove packets. The last removal erases the entry and job
completion retires any state for that job. A selected mark in mode
3 passes only if a strictly earlier step of the same job still has
a packet waiting on that port. The packet being dequeued is already
removed from the count. Mode 3 consumes the existing selection draw
before evaluating the gate. The progress estimator, probability,
ordinary queue ECN, and endpoint rate controller use the original
logic. Trajectories can diverge after the marking decision changes.

A queued packet is a direct signal of demand visible at the switch.
It can still be delayed by PFC or another priority. The gate can miss
a lagging flow whose next packet is arriving or still being paced.
It does not read sender state or predict future arrivals. It matches
any earlier step of the job, not just the current reference step.
This is an experimental extension, outside the paper's algorithm.

Telemetry
---------
Both schedulers now attach the same egress-bin trace. With
SYMPHONY_SCOPE_TRACE enabled, all 100 us bins with ring data
departures are emitted with output port, step bitmap, ring data
wire bytes and peak sampled device queue size. A missing bin means
no ring data departed. Port totals include control traffic. The
bitmap measures activity over a bin, not simultaneous queue
occupancy. The exact number of earlier-step packets still queued
is recorded when the probability draw selects a candidate. The
mark trace gives the reference step and the existing gap inputs,
along with the gate decision and final mark cause. Scope mode logs
all selected candidates and ordinary marks are counted separately.

Endpoint traces carry CNP receipt timestamps, cumulative transmitted
payload at CNP receipt, and the effective rate changes during decrease
and recovery. Per-flow rate samples and transmitted wire bytes are
retained in 1 ms bins. The payload after the last CNP is the
transmitted-payload counter at final ACK minus the value at last CNP.
The time measure runs from last CNP to final ACK and includes the
last feedback flight time. A flow without a CNP has no recovery tail.
The traces do not schedule events or draw random numbers.

Results
-------
  Seed    DCQCN CCT    Original CCT    Egress-aware CCT    vs original
    1      49.492 ms     75.485 ms         52.076 ms          -31.0%
    2      66.679 ms     81.068 ms         59.377 ms          -26.8%
    3      51.673 ms     67.289 ms         41.233 ms          -38.7%

  Seed   Original marks / no earlier packet queued   Egress-aware marks
    1                 2,991 / 2,881                              1,032
    2                 3,630 / 3,478                              1,194
    3                 2,115 / 2,026                                831

About 96% of original marks had no earlier packet queued at their
dequeue. That is a stricter condition than the earlier audit's 64%
with no earlier QP outstanding. Even the 100 us departure bitmap
contained no earlier-step traffic for 2,069 / 2,392 / 1,568 original
marks. These numbers measure observable traffic. They do not prove
the rejected packets would all have produced a net slowdown or that
no lagging traffic could have arrived later. In the modified runs
every applied Symphony mark had a waiting earlier packet. The
number of selected candidates suppressed by the gate is not a
counterfactual count of original marks, since schedules diverge.

Compared with original Symphony, the egress-aware mode left peak
logical overlap at 5 / 5 / 4 and raised mean overlap from
2.19 / 2.08 / 1.84 to 2.42 / 3.01 / 2.00. DCQCN-only means were
2.59 / 3.65 / 2.72. The queue mark counts were:

                 DCQCN      Original     Egress-aware
    Seed 1         247          184           102
    Seed 2         277           72           120
    Seed 3         243          118           115

Peak device queues were 94.7 / 87.0 / 92.3 kB under original and
76.5 / 94.3 / 96.4 kB under the gate. Congestion indicators changed
in both directions relative to original, with fewer queue marks
than DCQCN for all three seeds. The busiest switch-port utilization
rose from 34.5/32.1/38.7% to 50.0/43.8/63.1%. This is averaged over
the collective interval, so shorter CCT contributes to the higher
value. The per-port counters are in ports.json.

Recovery on each original-Symphony final flow, matched by flow ID:
  Seed / flow    Original duration and post-CNP tail   Egress-aware
    1 / 625          12.476 ms  (7.544 ms, 1,328,152 B)  1.835 ms, no CNP
    2 / 637          13.405 ms  (6.659 ms, 1,165,152 B)  2.557 ms, no CNP
    3 / 613          13.964 ms  (8.446 ms, 1,328,152 B)  4.154 ms
                                                           (3.460 ms, 1,906,152 B)

Original flow 625's rate increased after its last CNP and finished
at about 2.77 Gb/s. It received no CNP under the gate. In seed 3
the matched flow's tail carried more bytes under the gate, in less
time, with a rate reaching about 6.00 Gb/s after the last CNP.
The identity of the last flow changed with the gate. The actual
final flow in each egress-aware run received no CNP and finished
its transfer in about 1.762 ms.

The controlled change supports the hypothesis that the original
switch-wide scope penalized flows without an immediately available
consumer of the released egress bandwidth. DCQCN recovered rates
after the marks stopped, but often too late for the critical tail.
The gate improved every tested seed relative to original Symphony,
and two of three relative to DCQCN. It traded greater mean overlap
for shorter CCT at this scale. These runs do not establish the
result at 8 MB or for other workloads.

Reproduction and source
-----------------------
From the updated ns-3.19 checkout using the repository's Docker
or Python-2 Waf build environment:

  ./waf build
  LD_LIBRARY_PATH="$PWD/build" build/utils/ns3.19-test-runner-optimized \
    --suite=devices-point-to-point --verbose
  python3 -m unittest discover -s analysis -p test_figure4_workloads.py
  python3 analysis/run_figure4_workloads.py --build build \
    --output mix/output/symphony-scope --chunk 524288 --profiles D \
    --seeds 1 2 3 --workers 2 --symphony-scope
  python3 analysis/analyze_symphony_scope.py \
    mix/output/symphony-scope/bytes-524288/D \
    --output mix/output/symphony-scope/analysis

The test suite covers same and separate egresses, aligned packets,
job isolation and state removal, queue ECN with the gate closed,
and marking in original mode. The build needs tests enabled for
the C++ test runner.

  src/point-to-point/model/switch-node.cc/.h
      Queue state, the mode-3 gate and marking observation.
  src/point-to-point/model/qbb-net-device.cc
      Reports successful enqueues and drained packets.
  scratch/network-load-balance.cc, scratch/figure4-collective.h
      Scope config, shared egress registration and completion bytes.
  src/point-to-point/model/rdma-hw.cc/.h
      CNP byte snapshots and effective recovery rate transitions.
  src/point-to-point/test/point-to-point-test.cc
      Regression cases for marking and queue state.
  analysis/run_figure4_workloads.py, analysis/analyze_symphony_scope.py
      Matched treatment driver, trace joins and plots.

Saved analysis files are in analysis/figures/symphony-scope.
scope.csv has one row per run. flow-tails.csv matches flows across
treatments. ports.json contains directional utilization and queue
and mark counters. Raw scope-study logs and effective configs are
under /tmp/symphony-scope-study/bytes-524288/D.
